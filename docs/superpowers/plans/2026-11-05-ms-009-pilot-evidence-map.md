# MS-009 · Package G pilot evidence map (draft)

**Scope.** One local business, one customer-approved organic GBP text post, one occurrence. A second tenant exists only to expose isolation failures. The owner confirmed the text-only pilot for every role and one narrowly scoped administrator stop. The remaining rows translate design proposals into testable expectations. All cases below are **planned and unexecuted**. [Pilot decision](https://github.com/Maeximilion/MaexSocial/issues/8#issuecomment-6662099692) · [Stop decision](https://github.com/Maeximilion/MaexSocial/issues/30#issuecomment-6670980326) · [Package G assignment](https://github.com/Maeximilion/MaexSocial/issues/9#issuecomment-6671186754)

**Fixtures and stages.** Use synthetic tenants A/B, a member and workspace admin per tenant, a separately enrolled Windows admin on a disposable VM, test identity service, controlled clock and counting GBP fake. Reset between scenarios. Pin tenant, revision, location, timezone, instant and occurrence in the approval. At **G3 integration** (#10), record the resulting durable state, customer-visible status and fake calls. At **G3 staging** (#82), repeat applicable cases on the authorized artifact and owned surfaces before external access. A fake LIVE result proves only the local contract. G3 publication evidence needs a separately authorized, uniquely correlated Google-side observation. [Stage evaluations](../../08_EVALS.md) · [G2 work plan](2026-11-05-g2-work-plan.md)

## G3 integration · Approval to outcome

| Case / source | Synthetic control and failure sequence | Expected observation |
|---|---|---|
| Exact approval and concurrent claims · PLAN-01, ACCESS-03 | Approve A/r2 once, then twice with competing workers. Separately edit the text, change location or inject B into the queued job before claim. | Valid duplicates converge on one intent, at most one create and an A/r2 receipt. Each mismatch makes zero creates. Changed content or destination needs fresh approval. |
| Readback · PLAN-03 | Fake accepts the request and returns a resource name. Return processing, then LIVE for that resource and location. Separately return rejection or an unrelated LIVE resource. | Submission stays pending until a unique matching LIVE readback. Confirmation records resource, destination and observation time. Rejection is visible as rejected. An unrelated result cannot confirm A's post. |
| Access and export race · PLAN-03, ACCESS-02/03 | Remove the grant before dispatch. The permitted customer approver exports. Restore the grant and restart. Reverse the order so dispatch claims first, then the grant disappears. | Export-first returns approved text with “Exported — no Google publication confirmed” and permanently disables automated dispatch for that occurrence. Claim-first withholds export and further creates while reconciling the original attempt. |
| Lost response / restore · PLAN-03/04, ACCESS-03 | Lose the reply after fake acceptance, restart, then restore a pre-claim backup in isolation. Supply either unique readback or ambiguous matches. | Unknown survives restart. Restored work starts quarantined. One create across recovery, no manual export. Conclusive readback resolves the attempt, ambiguity stays visible and escalates. |
| Targeted admin stop · PLAN-04, ACCESS-05/08 | Enrolled admin selects tenant A and occurrence 1, gives reason and fresh MFA; commit stop before claim. Use a second otherwise eligible A occurrence as a control. Repeat with stale MFA, missing reason/target, failed audit persistence, then with dispatch already claimed. | Successful pre-claim stop yields a durable target/reason/outcome audit and zero creates for A/1. Other occurrence and B are unaffected. Invalid stop has zero management effect. A late stop cannot recall the write: preserve in-flight/unknown until reconciled. Admin cannot approve, release or send on the customer's behalf. |
| Organic-only and budget · ADS-01 | Approve the text and request paid activation or generation with zero authority. Separately simulate two 4-unit jobs competing for 5 authorized fixture units, a duplicate settlement and an unknown charge. | Organic path can proceed with zero paid calls. Unauthorized work incurs zero spend. In the budget simulation only one reservation succeeds, settlement applies once, unknown cost remains reserved. Fixture units authorize no real charge. |
| Disabled media · #43 | Submit one approved plain-text occurrence as the positive control. For every role, submit an attachment, media link, upload or foreign object reference through draft, export and dispatch. Probe guessed media routes. | Plain text follows the approved path. Reject every media input with zero media storage, fetches, jobs and charges. |
