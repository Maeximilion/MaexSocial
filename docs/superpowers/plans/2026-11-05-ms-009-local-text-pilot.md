# Local text pilot implementation plan · MS-009

**Goal.** Give #10 a repeatable synthetic demonstration of exact-revision approval for one GBP location, with visible confirmed or uncertain outcome. These future files and commands require separate implementation authorization.

**Architecture.** Plan from the selected strict TypeScript/Node baseline for the portal, API and worker: a modular service with two Express listeners (customer and private management), a separate Node worker and one PostgreSQL application transaction boundary. Keycloak uses a separate database/role and distinct customer and desktop OIDC clients. The enrolled Windows administrator operates from a separate signed application. [ADR 0001](../../decisions/0001-application-language.md) assigns TypeScript to browser/API/worker, SQL to migrations and C#/.NET 10 LTS/WPF to Windows 11. Python remains repository tooling. Cite the ADR and affected runtimes in implementation issues. The only GBP adapter is a deterministic local fake. [Owner's local selection](https://github.com/Maeximilion/MaexSocial/issues/8#issuecomment-6671380463) · [ADR 0002](../../decisions/0002-google-text-pilot.md) · [Access contract](../../17_ACCESS_SECURITY.md) · [Pilot evidence map](2026-11-05-ms-009-pilot-evidence-map.md)

**Local test proposals.** Use the ADR's Node 24, Express 5, PostgreSQL 17 and Keycloak 26.x candidates. Pin maintained patches/images and record lockfile and digests during implementation. Use two invented businesses A/B, a Manager and Employee in each, one enrolled fake operator, a controlled clock and a disposable Windows VM. Bind ingress to loopback or the isolated VM-only network, enforce TLS and deny external egress. Keep runtime credentials and disposable signing keys out of the repository. No cloud, external email, Google account, production signing, ad connector or paid service enters this run.

**Execution order.** Task 2 consumes task 1. Task 3 consumes tasks 1–2, including customer activation and approval. Task 4 consumes 1–3. Task 5 consumes 4. Task 6 proves the whole slice. For each task, write the named denial and allowed controls, observe failure, implement, rerun and commit. A missing service fails its prerequisite check. Before each targeted Node test, run `npm run pilot:build` and require successful compilation. Restart any running application processes from that build before integration assertions. A compile error is a failed prerequisite. Add each task’s test source before its first build. Record fixture, build SHA, command, expected/observed state and side-effect counts per case.

**File and test convention.** Create these paths only after implementation authorization. Each compiled Node test at `dist/pilot/tests/pilot/<case>.test.js` comes from `tests/pilot/<case>.test.ts`. Keep build output and ephemeral DB, package and identity fixtures outside version control. The .NET tests and Windows package check in task 3 use the same HTTP contract and synthetic fixture data.

The fake provider's independent store survives worker restart and app-database restore. Introduce only customer/management/worker privileges actually used. The browser and desktop get no DB or worker credentials.
- [ ] Create `db/migrations/001_pilot.up.sql`, `db/migrations/001_pilot.down.sql` and `scripts/pilot-db.ts`. Store versioned tenant memberships (Manager or Employee), pending account/access requests, invitations (hashed single-use token, bound issuer, tenant, email, role, purpose, grant version and expiry), enrolled devices and sessions, locations/grant versions, immutable draft revisions, approvals, occurrences, attempts, audit, budget reservations and a dispatch-stop flag. Use composite tenant/object foreign keys for related records. Enforce globally unique, server-generated immutable occurrence IDs in the DB, with composite tenant/ID reference keys and one attempt per occurrence. Approvals reference the same occurrence across edits and restarts; simultaneous due times do not merge distinct occurrences. Evaluate authority and every hold/export/claim transition under the same transaction lock. Serialize grant/role/stop updates with the claim so a revocation committed first wins. Couple management audit to the mutation.
- [ ] Define `npm run pilot:build` as strict `tsc -p tsconfig.pilot.json`, with repository-relative source layout emitted to `dist/pilot/`. The target includes pilot scripts, applications and tests. Define `npm run pilot:up` and `pilot:down` to start/stop the isolated stack (no volume deletion); `pilot:migrate -- up|down` runs the selected SQL against only the local fixture DB. Refuse a non-fixture database for destructive drills.
- [ ] From the repo root run `npm ci`, `npm run pilot:build`, `npm run pilot:up`, then on an **empty disposable DB** run `npm run pilot:migrate -- up`, `npm run pilot:migrate -- down`, `npm run pilot:migrate -- up`. Run `node --test dist/pilot/tests/pilot/storage.test.js`: seed A/B, reject cross-tenant references and B reusing A’s occurrence ID; accept B with a different ID. Race two inserts for one occurrence. Expect rejection and one durable occurrence; verify the IdP DB is inaccessible to the app role. Down on real or populated customer data is outside this drill.

On verified activation invalidate every pending credential, authenticator, challenge and session from unverified preregistration, including when the user activates via an invitation. For an already verified identity, require authenticated acceptance as that identity and add only the invited membership. Require any missing first or last name. - [ ] In `apps/web/src/routes/portal.ts` define `POST /customer/employees/invitations` (email) and `DELETE /customer/employees/:membershipId`. Only an active Manager may invite an Employee to, or revoke an Employee from, the Manager’s own tenant. Bind Employee role and tenant at the server; deny promotion, Manager removal and cross-tenant writes. Use the proposed customer MFA policy: authenticate enrollment with current credentials, then require fresh MFA before Employee invitation/removal or post approval. Following recovery, restore MFA before those actions resume. Test absent enrollment, expired proof and recovered-but-unenrolled sessions against each action. Display the invited tenant and role. Serialize redemption with issuer revocation, role changes and tenant suspension. At redemption atomically consume the invitation only if its version, tenant and issuer authority remain current. A competing invitation cannot overwrite an existing role. Revoke this Employee’s outstanding invitations for the target tenant and deny its next protected request there, including through an existing session. Preserve other memberships. Deliver only to the isolated mailbox sink; disable external mail transport.
- [ ] Define `POST /customer/drafts` (plain text and own authorized location), `POST /customer/occurrences/:id/approval` (revision, location, local timezone and UTC due instant) and `GET /customer/occurrences/:id` (own state). Snapshot the exact values the customer saw. Only an active Manager of the target tenant may approve with fresh MFA. An Employee can edit an own-tenant draft but cannot approve it. Both roles may export under task 4. Test the approval endpoint directly with the Employee and DEV/Admin credentials; neither creates approval or queues a job. Repeating an approval under the same current Manager grant/version returns the existing intent. After grant invalidation, explicit reapproval binds the existing unclaimed occurrence to the new approval and cannot create a second occurrence. An edit or destination/time change invalidates prior approval before claim. Reject attachments, media links for ingestion, uploads and object references for **all** roles on draft/approval requests, including direct requests bypassing UI. - [ ] Run `node --test dist/pilot/tests/pilot/portal.test.js`. Only a successful or previously terminal authorized export returns its immutable text. Worker wakes carry the global occurrence ID. Resolve tenant from its stored row. - [ ] In `packages/contracts/pilot.ts`, define `ApprovedIntent` (tenant, stable occurrence ID, immutable revision and text, authorized location, due instant/zone, approver, Manager membership/version at approval and separate provider grant version), `Receipt` (attempt, location, optional resource name) and `Observation` (location, resource name when known, state, observed instant and correlation evidence). Use a barrier at claim commit, before create, after acceptance and before reply to make the crash/race assertions repeatable.
- [ ] Claim path: scheduled → submitting (commit one attempt) → fake create **once**, with automatic transport retries disabled. Only the successful claiming invocation can create. Recovery treats an existing attempt as read-only even if it lacks a receipt. Fake contract: `create(intent): Promise<Receipt>`, `readback(attempt): Promise<Observation>`. Include correlated resource/location, observed time and processing/LIVE/rejected/ambiguous modes. Store our consent/attempt/audit facts separately from provider data. It returns only the stored approved revision. Restoring the grant cannot send it. A held occurrence cannot bypass its hold through export. Portal shows held/submitting/processing/confirmed/rejected/unknown separately; escalation identifies the original unresolved attempt.

Stop worker/ingress separately, record unresolved attempts and revoke affected test sessions/grants. Re-open only by explicit local fixture action after isolation/readiness checks. Process restart alone cannot clear the stop.
- [ ] Provide `npm run pilot:backup` and `npm run pilot:restore` restricted to the isolated fixture. Snapshot app DB and matching IdP build/config/database. Restore with ingress and dispatch disabled, quarantine **all** historical occurrences (even apparently unsent), replay the independent history and rotate stale credentials before reads. Ambiguous historical work stays quarantined; release would require independent proof neither export nor dispatch was claimed, current authority and approval. A negative provider lookup cannot supply that proof.
- [ ] Run `node --test dist/pilot/tests/pilot/recovery.test.js`. Stop while one attempt is in flight: block all new claims, reconcile the original without a second create. Restore snapshots taken **before** later dispatch, terminal export, deletion or grant/device revocation. After reconnect expect 1 create total for the dispatched case and 0 for exported, deleted or revoked cases. With incomplete independent history keep affected reads/jobs disabled. Expired provider data stays inaccessible. Demonstrate a compatible previous app/schema and matching IdP restore using synthetic data; an incompatible binary stays offline. Record measured data loss/time, build SHAs, isolation and health before explicit reopening. Acceptance thresholds for real operation belong to Maxi.
