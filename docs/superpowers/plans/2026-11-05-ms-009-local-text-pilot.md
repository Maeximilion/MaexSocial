# Local text pilot implementation plan · MS-009

**Goal.** Give #10 a repeatable local demonstration: a synthetic customer approves one exact text revision for one GBP location and sees the outcome, including the case where the outcome cannot be determined. This document specifies future files and commands. Their creation and execution require a separate implementation decision.

**Architecture.** Plan from the selected strict TypeScript/Node baseline for the portal, API and worker: a modular service with two Express listeners (customer and private management), a separate Node worker and one PostgreSQL application transaction boundary. Keycloak uses a separate database/role and distinct customer and desktop OIDC clients. The enrolled Windows administrator operates from a separate signed application. Use the [#100 language selection](https://github.com/Maeximilion/MaexSocial/issues/100) pending integration of its documentation PR: strict TypeScript in the browser, strict TypeScript/Node in the API and separate worker, PostgreSQL SQL for schema/migrations and C#/.NET 10 LTS with WPF for the Windows 11 app. Python remains repository tooling. Reconcile the integrated decision before implementation. The only GBP adapter is a deterministic local fake. [Owner's local selection](https://github.com/Maeximilion/MaexSocial/issues/8#issuecomment-6671380463) · [ADR 0002](../../decisions/0002-google-text-pilot.md) · [Access contract](../../17_ACCESS_SECURITY.md) · [Pilot evidence map](2026-11-05-ms-009-pilot-evidence-map.md)

**Local test proposals.** Use the ADR's Node 24, Express 5, PostgreSQL 17 and Keycloak 26.x candidates. At implementation, pin maintained patches/images and record the lockfile and digests. Use two invented businesses A/B, a member and a workspace admin in each, one enrolled fake operator, a controlled clock and a disposable Windows VM. Bind ingress to loopback or the isolated VM-only network, enforce TLS and deny external egress. Keep runtime credentials and disposable signing keys out of the repository. No cloud, external email, Google account, production signing, ad connector or paid service enters this run.

**Execution order.** Tasks 2 and 3 consume task 1. Task 4 consumes 1–3. Task 5 consumes 4. Task 6 proves the whole slice. Each future implementer first writes the named negative and allowed control, runs the targeted command to observe the missing behavior, implements the smallest passing change, reruns it and commits that task. A missing service is a failed prerequisite, never a skipped acceptance case. Record fixture, build SHA, command, expected/observed state and side-effect counts per case.

**File and test convention.** Proposed paths below belong to the implementation worktree only after authorization. Each compiled Node test at `dist/pilot/tests/pilot/<case>.test.js` comes from `tests/pilot/<case>.test.ts`. Keep build output and ephemeral DB, package and identity fixtures outside version control. The .NET tests and Windows package check in task 3 use the same HTTP contract and synthetic fixture data.

## 1. Reproducible isolated environment and storage

- [ ] Create `package.json`, `package-lock.json`, `tsconfig.pilot.json`, `ops/local/compose.yaml`, `ops/local/keycloak-realm.json` and `tests/pilot/fixtures.ts`. Provide local Postgres, Keycloak with private management, a mailbox sink, isolated TLS and temporary per-run credentials. The fake provider's independent store survives worker restart and app-database restore. Introduce only customer/management/worker privileges actually used. The browser and desktop get no DB or worker credentials.
- [ ] Create `db/migrations/001_pilot.up.sql`, `db/migrations/001_pilot.down.sql` and `scripts/pilot-db.ts`. Store memberships/roles, enrolled devices and sessions, locations/grant versions, immutable draft revisions, approvals, occurrences, attempts, audit, budget reservations and a dispatch-stop flag. Use composite tenant/object foreign keys for related records. Key each occurrence by tenant and immutable occurrence ID, unique attempt per occurrence. Approvals reference the same occurrence across edits and restarts; simultaneous due times do not merge distinct occurrences. Evaluate authority and every hold/export/claim transition under the same transaction lock. Serialize grant/role/stop updates with the claim so a revocation committed first wins. Couple management audit to the mutation.
- [ ] Define `npm run pilot:build` as strict `tsc -p tsconfig.pilot.json`, with repository-relative source layout emitted to `dist/pilot/`. The target includes pilot scripts, applications and tests. Define `npm run pilot:up` and `pilot:down` to start/stop the isolated stack (no volume deletion); `pilot:migrate -- up|down` runs the selected SQL against only the local fixture DB. Refuse a non-fixture database for destructive drills.
- [ ] From the repo root run `npm ci`, `npm run pilot:build`, `npm run pilot:up`, then on an **empty disposable DB** run `npm run pilot:migrate -- up`, `npm run pilot:migrate -- down`, `npm run pilot:migrate -- up`. Run `node --test dist/pilot/tests/pilot/storage.test.js`: seed A/B, attempt a cross-tenant reference and two competing inserts for one occurrence. Expect rejection and one durable occurrence; verify the IdP DB is inaccessible to the app role. Down on real or populated customer data is outside this drill.

Use the local Keycloak browser flow, code/state/nonce, fixed return target and opaque, rotated Secure/HttpOnly/SameSite cookies. Bind writes to CSRF proof and origin. Invite/signup input cannot grant a role, join an existing workspace by email domain or provision a platform admin.
- [ ] Through the mailbox sink verify single-use identity/purpose-bound challenges, explicit redemption (GET is read-only), atomic activation, resend invalidation and reset/logout revocation. Discard credentials/authenticators/sessions supplied before mailbox verification; establish the verified user's new credential. Independently enforce account/source throttles for present and absent identities. Use #30's candidate clock values for tests only (e.g. 24 h verification, 15 min reset, 30 min idle/8 h total customer session).
- [ ] Define `POST /customer/drafts` (plain text and own authorized location), `POST /customer/occurrences/:id/approval` (revision, location, local timezone and UTC due instant) and `GET /customer/occurrences/:id` (own state). Snapshot the exact values the customer saw. Candidate approver is the active workspace admin, with fresh customer MFA; a member can edit own drafts. Repeating the same approval returns the existing intent. An edit or destination/time change invalidates prior approval before claim. Reject attachments, media links for ingestion, uploads and object references for **all** roles across draft/export/dispatch, including direct requests bypassing UI.
- [ ] Run `node --test dist/pilot/tests/pilot/portal.test.js`. Cover ACCESS-01/02/04/06/07/09/10/12/13/14 and PLAN-01: keyboard-only signup through dashboard, legitimate approval, concurrent token redemption, attacker preregistration, stale cookie, role injection, cross-origin login/write, B's guessed ID/export, missing/expired MFA and media payloads. Assert only verified A's workspace activates once, B stays private; denied actions leave no mutation, media job, fetch or charge. Inspect synthetic canaries in responses/logs/exports and check expiry and public rate-limit response equivalence. Exercise legitimate operations after denial.

## 4. One dispatch claim, terminal export and read-only reconciliation

- [ ] Extend the task 3 transitions in `packages/contracts/occurrence.ts`. Create `apps/worker/src/main.ts`, `apps/worker/src/dispatch.ts`, `apps/worker/src/reconcile.ts` and `tests/pilot/fake-gbp.ts`. Expose `claimDispatch(occurrenceId, now)`, `holdOccurrence(adminProof, tenantId, occurrenceId, reason)` and `claimExport(customerSession, occurrenceId)`. Each returns the committed state. Only a successful or previously terminal authorized export returns its immutable text. Worker wakes carry only an occurrence ID. Reload tenant, location, current approving membership, approved revision, active grant, due time, stops and cost authority at claim.
- [ ] In `packages/contracts/pilot.ts`, define `ApprovedIntent` (tenant, stable occurrence ID, immutable revision and text, authorized location, due instant/zone, approver and grant version), `Receipt` (attempt, location, optional resource name) and `Observation` (location, resource name when known, state, observed instant and correlation evidence). Parse data at the boundary and load trusted bindings from storage. Only the fake worker receives a usable grant reference. Key its counter by tenant and occurrence. Use a barrier at claim commit, before create, after acceptance and before reply to make the crash/race assertions repeatable.
- [ ] Claim path: scheduled → submitting (commit one attempt) → fake create **once**, with automatic transport retries disabled. Only the successful claiming invocation can create. Recovery treats an existing attempt as read-only even if it lacks a receipt. Fake contract: `create(intent): Promise<Receipt>`, `readback(attempt): Promise<Observation>`. Include correlated resource/location, observed time and processing/LIVE/rejected/ambiguous modes. Store our consent/attempt/audit facts separately from provider data. Confirm only unique, independently read LIVE; same text/time, missing ID, expired correlation evidence or empty readback remains pending/unknown as appropriate. Never release export after dispatch.
- [ ] Export path: `POST /customer/occurrences/:id/export` checks customer authority, exact approval, missing access and **no prior claim**, commits terminal exported state before releasing the text. Show “Exported — no Google publication confirmed”. Re-download returns the same revision after reauthorization. Restoring the grant cannot send it. A held occurrence cannot bypass its hold through export. Portal shows held/submitting/processing/confirmed/rejected/unknown separately; escalation identifies the original unresolved attempt.
- [ ] Run `node --test dist/pilot/tests/pilot/dispatch.test.js`. Use DB barriers, independent worker connections and a persistent fake call counter, never timing sleeps. Assert the following sequences (ACCESS-03/05, PLAN-01/03/04, #43). For blocked rows verify zero leaked manual text and no B mutation where applicable.

| Sequence | Expected create count for A1 and visible result |
|---|---|
| Duplicate approval, two workers claim; separately edit/revoke before claim | Valid path exactly 1, only one intent and receipt; stale path 0, held pending new authority |
| Admin hold commits first vs claim first; repeat with stale MFA, missing reason and failed audit | Valid first hold: 0, A1 held and independent A2 still eligible. Claim first: at most 1, original attempt visible. Invalid hold: no hold/audit success or management mutation |
| Missing grant, export wins vs dispatch wins; reconnect | Export wins: 0 forever, same approved text. Claim wins: at most 1, no manual-submission output, reconcile |
| Crash after claim commit but before create vs fake accepts then drops reply | 0 vs 1. Both recover as uncertain, make no further create and withhold export |
| Fake returns processing then correlated LIVE; repeat rejection or unrelated LIVE | 1 create per fresh fixture; processing → confirmed only on correlated readback; rejection visible; unrelated LIVE never confirms |
| Media payload injected on direct API or queued reference | 0 media storage/fetch/jobs/charges across all roles. Approved plain text still reaches fake |

## 5. Local shutdown, rollback and isolated restore

- [ ] Create `ops/local/recover.ts`, `ops/local/backup.ts` and `tests/pilot/recovery.test.ts`. Provide `npm run pilot:stop-dispatch` to atomically set a durable stop before new claims; leave reconciliation available for existing attempts. Stop worker/ingress separately, record unresolved attempts and revoke affected test sessions/grants. Re-open only by explicit local fixture action after isolation/readiness checks. Process restart alone cannot clear the stop.
- [ ] Provide `npm run pilot:backup` and `npm run pilot:restore` restricted to the isolated fixture. Snapshot app DB and matching IdP build/config/database. Maintain a separately retained deletion/revocation history covering the full backup horizon, independent of the restored DB. Restore with ingress and dispatch disabled, quarantine **all** historical occurrences (even apparently unsent), replay the independent history and rotate stale credentials before reads. Ambiguous historical work stays quarantined; release would require independent proof neither export nor dispatch was claimed, current authority and approval. A negative provider lookup cannot supply that proof.
- [ ] Run `node --test dist/pilot/tests/pilot/recovery.test.js`. Stop while one attempt is in flight: block all new claims, reconcile the original without a second create. Restore snapshots taken **before** later dispatch, terminal export, deletion or grant/device revocation. After reconnect expect 1 create total for the dispatched case and 0 for exported, deleted or revoked cases. With incomplete independent history keep affected reads/jobs disabled. Expired provider data stays inaccessible. Demonstrate a compatible previous app/schema and matching IdP restore using synthetic data; an incompatible binary stays offline. Record measured data loss/time, build SHAs, isolation and health before explicit reopening. Acceptance thresholds for real operation belong to Maxi.
