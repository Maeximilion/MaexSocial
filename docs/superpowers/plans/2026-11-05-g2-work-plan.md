# G2 design and acceptance work plan

**Goal.** Give Maxi enough evidence to select one buildable customer journey, and give the MS-009 author a checked design to turn into an executable first-slice plan. The checkboxes below track planning deliverables. Future product tests are acceptance criteria, not observed results.

**Architecture and stack.** Use [ADR 0001](../../decisions/0001-application-language.md) and the [planning brief](../specs/2026-11-05-g2-planning-design.md). TypeScript strict is established. A modular application with a durable worker is recommended. [Maxi confirmed the pilot assumption](https://github.com/Maeximilion/MaexSocial/issues/8#issuecomment-6662099692): one local business, one approved GBP text post and an independently verifiable Google-side result. Without access before dispatch, export with an explicit unconfirmed status and permanently disable dispatch for that occurrence. If dispatch may already have happened, withhold export and reconcile. Live eligibility, hosting, identity, admin packaging, retention and spending limits remain open. Use separate issues for design acceptance, implementation planning and gate acceptance.

#### Worked acceptance examples for MS-009

| Synthetic input | Observable result to require |
|---|---|
| A approves revision 2 twice for the same destination and occurrence. Two workers claim the job | One intent and at most one create attempt. The receipt belongs to A and revision 2 |
| A edits revision 2 into revision 3 before dispatch or revokes the grant | The old approval cannot send revision 3. A revoked grant causes zero creates and a visible hold |
| A hold commits before the worker claims dispatch; repeat with a hold immediately after dispatch is recorded | First case: zero sends. Second case: show in-flight/unknown until reconciliation, stop later work and never claim to have recalled the post |
| Export and dispatch race on the same occurrence while the grant is unavailable | If export claims it first, a restored grant still permits zero automated sends. If dispatch claims it first, manual export is refused and the same attempt is reconciled. Never offer both paths for one occurrence |
| A provider accepts a request but the worker loses the response | Persist unknown outcome across restart. A conclusive readback can resolve it; if no unique match exists, escalate and issue zero further creates |
| Two synthetic jobs each reserve 4 units against a 5-unit remaining limit | At most one 4-unit reservation and billable dispatch. A duplicate callback settles it once. Unknown cost stays reserved for reconciliation |
| A customer session presents B's export ID or calls the PC management endpoint directly | No B payload or management effect. The enrolled administrator can perform only the allowed action on the explicit target and generates an audit event |
