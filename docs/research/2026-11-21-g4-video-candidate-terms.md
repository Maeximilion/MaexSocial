## Common example and price

Use one operator-created, rights-cleared JPEG of a fictional carton with a two-word label and a color stripe, 1280 × 720, with metadata stripped. Use a short, manually written camera-motion prompt. Request one five-second, 16:9, 720p clip without generated sound, extra shots, upscaling or other models. The target is 1280 × 720 in MP4. A model that does not document the exact output dimensions or codec has an acceptance gap. This example is a price comparison and a proposed test input. It grants no access, transfer or spending authority.

## Runway Dev · Gen-4.5

- **API and media.** The public catalog lists `gen4.5`. The task uses `POST /v1/image_to_video`, a server-side project key and API version `2024-11-06`. The model supports 2–10 seconds and explicitly supports the target `1280:720`. Send the JPEG as an inline data URI within the documented size limit. PNG and WebP are also accepted image encodings. Direct inline input avoids a separately hosted input URL. The alternative ephemeral `runway://` upload reference lasts 24 hours from creation. The default output is SDR H.264 MP4. Account access and the model's exact internal revision are unknown. [API reference](https://docs.dev.runwayml.com/api/) · [Model release](https://docs.dev.runwayml.com/changelog/#gen-45-on-runway-dev) · [Inputs](https://docs.dev.runwayml.com/assets/inputs/) · [Uploads](https://docs.dev.runwayml.com/assets/uploads/) · [Output formats](https://docs.dev.runwayml.com/guides/professional-outputs/)
- **Private capture and deletion.** An authenticated task lookup returns an expiring output URL. The example shows a signed CDN link. Treat possession of that link as access and keep it server-side. The published window is 24–48 hours after accessing the API. Capture promptly into approved private storage and verify the content before serving it under MaexSocial authorization. Deleting a finished task removes its output from persistent storage under Runway's retention policy. Expiring URLs and a task deletion response establish no purge deadline for copies, backups, prompts or inputs. The self-serve processing region, precise persistence of those data, and revocation of issued links remain unknown. Runway Dev describes zero retention and no training under Enterprise agreements. [Task management](https://docs.dev.runwayml.com/api/) · [Output URLs](https://docs.dev.runwayml.com/assets/outputs/) · [Enterprise API](https://dev.runway.com/enterprise)
- **Usage rights and terms.** Runway's Terms of Use (updated 2026-10-23) explicitly cover its APIs and allow commercial use of outputs subject to the terms and usage policy. The operator must have rights to the inputs. Runway claims no ownership of inputs or outputs and reserves a broad license for uses including training. Confirm account-specific terms before accepting these conditions for any transfer. Customer-facing API integration has the applicable attribution and end-user obligations. The proposed operator-only trial supplies a synthetic asset with no real person, trademark, customer fact or publication. [Terms of Use §§1, 4 and 5](https://runway.com/terms-of-use) · [Runway Dev commercial use](https://dev.runwayml.com/learn/commercial-use) · [API attribution](https://docs.dev.runwayml.com/usage/attribution/)
- **State and billing.** Task polling should be no more frequent than once per five seconds. `DELETE` can cancel pending, throttled or running tasks. Refund eligibility uses the server's state at cancellation. A running task receives no refund, completed-task deletion does not refund, and even successful cancellation may race with execution. Input safety failures can consume credits. On lost response, timeout or uncertain charge, preserve the single attempt, inspect the existing task if identifiable and reconcile the isolated project's usage. An opaque request tag can help attribute usage, but a missing report row does not prove the request never ran. No repeat submission in this proposed trial. [Task management](https://docs.dev.runwayml.com/api/) · [Task failures](https://docs.dev.runwayml.com/errors/task-failures/) · [API request tags and spend](https://docs.dev.runwayml.com/usage/request-tags/)

## Higgsfield API · Kling 3.0 Standard

- **API and media.** The model's REST/SDK schema accepts a required `image_url` such as a JPEG URL, 3–15 whole seconds, a `sound` toggle (default on) and `multi_shots` (default false). It has no resolution or aspect-ratio field. It returns an asynchronous request ID and a completed `video.url`. The shared lifecycle documentation shows an MP4 example. The public Standard specification gives a 720p class. Final dimensions/aspect ratio for this input, model-specific container/codec guarantees, account access and internal model revision are unknown. [Model API reference](https://open.higgsfield.ai/models/kling-video/v3.0/std/image-to-video/api-reference) · [Model text reference](https://dash.higgsfield.ai/models/kling-video/v3.0/std/image-to-video/llms.txt) · [Request lifecycle](https://docs.higgsfield.ai/docs/concepts/requests)
- **Input delivery and private output.** The provider's upload flow accepts JPEG and returns a one-hour presigned **write** URL and a separate `public_url` for the model to read. The one-hour window says nothing about expiry of the public read link. Private retrieval of a scoped operator-hosted input by this exact model remains unverified. API Terms §7.4 describes generated-media URLs as private/access-controlled by default and available for at least seven days. Technical docs describe seven days by default from terminal state, shortening to as little as one hour with `Hf-Expires-After`, and `expires_at` as the URL cutoff. Confirm the effective retention on the approved account and request before relying on the shorter window. The exact CDN read authentication, sharing and early revocation behavior are undocumented in the reviewed sources. Keep all provider URLs server-side and require private capture under MaexSocial access checks. [File uploads](https://docs.higgsfield.ai/docs/concepts/file-uploads) · [API Terms §7](https://open.higgsfield.ai/terms-of-service) · [Retention and expiry](https://docs.higgsfield.ai/docs/enterprise/data-retention)
- **Deletion and usage rights.** Default expiry removes request files. Shortened retention or explicit DELETE of a finished request also removes prompts and parameters. Request IDs, lifecycle metadata and billing survive. Standalone uploads and reusable input copies are separate and documented to be deleted within seven days. The API Terms (updated 2026-09-02) supplement the consumer Terms of Use. They require a developer application to add material functionality and restrict standalone resale and direct exposure of API access. They permit commercial use of output subject to terms and require rights-cleared inputs and applicable disclosure/provenance. They do not warrant originality or non-infringement. Workspace training exclusion is off by default, with up to 10 business days for processing and prospective effect only. The model reference tags this as a partner model. The applicable upstream training, deletion and processing region remain unverified. [Retention and deletion](https://docs.higgsfield.ai/docs/enterprise/data-retention) · [API Terms §§1, 4–7 and 12](https://open.higgsfield.ai/terms-of-service) · [Training controls](https://docs.higgsfield.ai/docs/enterprise/model-training) · [Model text reference](https://dash.higgsfield.ai/models/kling-video/v3.0/std/image-to-video/llms.txt)
- **State and billing.** Higgsfield documents charging for successful requests, returning any reserved amount for `failed` or `nsfw`, and refunding successful queued cancellations. Cancellation is queued-only. Verify terminal state instead of treating the cancellation receipt as confirmation. The documented idempotency key can return the original ID when the same request is replayed under its constraints. Preserve that key for traceability and keep any unknown acceptance or charge unresolved pending status and billing evidence. The proposed one-submission rule still forbids an automatic replay. [Request lifecycle](https://docs.higgsfield.ai/docs/concepts/requests) · [Idempotency](https://docs.higgsfield.ai/docs/concepts/idempotency) · [Billing and retention](https://docs.higgsfield.ai/docs/concepts/billing-and-retention)

## Decision for #167

| Candidate | Disposition and prerequisites for a future trial |
| --- | --- |
| **Runway Dev Gen-4.5** | **Propose for one conditional operator-only trial.** Inline JPEG avoids a public input URL, the API pins the target dimensions and format, and the unit calculation is explicit. After G3 acceptance and separate owner authority, confirm account/model eligibility, effective rate, contract/data-use and region, and the acceptable deletion/retention limits for this synthetic material. Use an isolated project with auto-billing off and a separately approved purchase only if needed. The owner must approve the test window, budget (proposed generation cap 60 credits), input/custody, cancellation and charge-reconciliation owner, and acceptance rubric. Stop before transfer if any prerequisite is missing or the price exceeds the approved cap. |
| **Higgsfield API Kling 3.0 Standard** | **Defer this one trial.** Require evidence for scoped input retrieval, private output access/revocation, exact output properties, the applicable upstream processing terms and an exact account estimate before reconsidering. Its lower listed price alone cannot establish those prerequisites. This removes no later evaluation option under #167. |

For #11, freeze the fixture hash, prompt, model identifier and expected output before authorization. Proposed acceptance is one submission, one attributable charge within cap, terminal result within ten minutes of polling, private validated capture and an explicit cleanup receipt or open deletion gap. Validate MP4, 1280 × 720 and five seconds ±0.25 s. A human checks visible motion and the original label, stripe and carton shape at the opening, middle and closing frames, with no invented offer. Treat missing measurements, uncertain execution or charge, and a missed threshold as unresolved or failed. Application code retains tenant and role checks, provenance and revision binding, media validation, budget reservation, stop and single-attempt reconciliation. A model result cannot grant authority. An authenticated model API or server SDK is the proposed transport for #11. MCP and the development Claude review workflow have no product invocation or approval role.
