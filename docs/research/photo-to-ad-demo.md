## Proposed later spike · one Runway API task

**Question:** Can one owned product photo yield a five-second, recognizable moving product shot within a known generation budget? Runway is a test fixture because it publishes a model-specific rate and a concrete API request. The result would test one component of an ad, without inferring Claude/MCP parity, provenance of the remembered post, or a G2 provider choice.

1. **Preflight and stop conditions.** Obtain separate owner approval for the transfer, processor terms/retention, test window and cost. Use an isolated Runway Dev project, project key from a secret store, sufficient API credits and auto-billing off. Confirm the model is available and recheck its rate. Runway lists a minimum **USD 10** initial credit purchase, with possible tax. Use existing credits or stop for a separately approved purchase. [Project setup](https://docs.dev.runwayml.com/guides/setup/) · [API pricing](https://docs.dev.runwayml.com/guides/pricing/).
2. **Freeze input and request.** Photograph a plain, rights-cleared test carton with a fictional two-word label and colored stripe, no people or location data. Save a metadata-stripped 1280×720 JPEG privately and record its SHA-256. Use the same bytes as a data URI for `promptImage`. Submit once to `POST /v1/image_to_video`, version `2024-11-06`, model `gen4.5`, ratio `1280:720`, duration `5`, default output, prompt: “Slow camera push toward the carton on the table. The carton stays still and fully in frame. Keep the printed label and stripe intact.” Record the exact inputs privately. A repeated setup can yield different pixels. [Request and data URI example](https://docs.dev.runwayml.com/guides/using-the-api/).
3. **Bound the spend.** At the 2026-11-05 API list price, 5 seconds × 12 credits/second = **60 credits (USD 0.60 before tax)**. Maximum one submission and 60 credits, zero automatic retries or extra image/audio/render tasks. A changed price above the cap, insufficient balance or an ambiguous submission ends the experiment. Reconcile the existing task and billing before any new authorization. [Model rate and credit price](https://docs.dev.runwayml.com/guides/pricing/).
4. **Observe and score.** Record start/end time, task ID and status privately. Poll only that ID for up to ten minutes. A timeout is unresolved and may still be billable. On success, copy the expiring result to approved private storage. Check duration (5 s ± 0.25), dimensions (1280×720) and visible motion. Compare frames near 0, 2.5 and 4.9 seconds to the source: both label words legible and unchanged, stripe color and carton shape preserved, no new product or invented offer. Fail on any miss. Record actual credits, elapsed time, output hash, per-check result and scheduled deletion of private inputs/outputs. If a charge cannot yet be reconciled, mark cost unknown. [Task output lifecycle](https://docs.dev.runwayml.com/assets/outputs/) · [MaexSocial media boundaries](../security/uploads.md).

This investigation used public reads only. No provider account, connector, generation, publication or payment was initiated. Spike quality, latency, actual billing and provider-side deletion remain untested.
