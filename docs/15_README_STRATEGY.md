# README and assets

The README introduces MaexSocial, states the current stage, links the project and documents the working setup. Product goals must be labeled as planned until an implementation and its acceptance evidence exist.

## Visual direction

Use original MaexSocial SVG assets under `.github/assets/`, a readable wordmark/banner, accessible alternative text and repository-relative image paths. The Maex-Voice-Agent reference supplies layout conventions. Its restaurant imagery, capability charts and measured values do not belong to MaexSocial.

## Required content

- Product purpose and intended audience.
- Current gate, implemented foundation and next research step.
- Workflow from discovery through synthesis, approved design and build.
- Repository and project links, actual check badges and documentation entry points.
- How to begin the current phase, using commands that work from a clean checkout.
- Contribution, security and license references.

## Maintenance

Update README status when a gate passes or an advertised capability changes. Every displayed metric needs a dated source. A static diagram describing a planned workflow must say planned. Validate local image/document links and inspect newly created visual assets. Saving a social-preview file does not upload it to GitHub repository settings. Record an upload separately if performed.

Keep the first foundation version concise. Add product screenshots and performance charts only when the application produces them.
