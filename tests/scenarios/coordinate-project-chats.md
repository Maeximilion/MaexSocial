## Expected decisions

- Authority: the assigned worker selects this adapter for controls/relay verification, applies receiver/current-control rules without loading the personal loop or taking ownership, and does not select it for an unrelated notification. The acting coordinator starts with the repository entry/adapter and checks the two-file set and both hashes against the sole authoritative table, not a historical handover. A changed edition stays inactive until an independent fresh review of its actual body/metadata is recorded and the pin-update maintenance PR is merged; no Main self-review or ledger-only approval. Inspect preserved local/dirty/unpublished checkpoints and newer record PRs; a genuine newer local pause wins over an older published resume. Superseded controls are historical. Verify sender, assignment and newest control; report conflicting relays locally and reply only to the verified coordinator. Repository policies override the personal skill. Competing takeover holds dispatch/merge until relinquishment and in-flight reconciliation.
- Intake: admit at 600 seconds if authority, task, quota and capacity permit; no PR token is needed. Read current shared usage first; unknown readings or 7% remaining hold new intake under the standing rule. Count uncertain creation once and reconcile its outcome/start before another reservation. No accumulated missed-tick batch. Five slots, the lower large-work cap or the latest drain rule prevent admission as applicable.
- Discovery: query Graphify with `Maeximilion/MaexSocial`, compare SHA/coverage, read changed source and required unindexed documents locally, and report fallback. Confirm paths rather than guessing. Use a separate task worktree; preserve canonical and foreign work.
- Decisions: do routine authorized work; prefer brief questions, meaningful milestones/completion reports and answers via send_message_to_thread in both authorized directions. Attempt each message once, with no repeat on an uncertain result or self-handling of a native prompt/blocker. Missing authorization/tooling or blocked/uncertain sending falls back to the question/result in its originating chat and bounded wait_threads/targeted read_thread; no continuous polling or tool-free channel is promised. Track receipt separately from acknowledgment. Main decides delegated matters without an owner round trip. Change the failed work approach with new evidence; escalate new paid authority only while independent work continues.
- Permissions: report the actual restricted worker turn, not inherited/global full access. Request supported High/Standard settings and verify runtime separately. Use only the authorized app setting and inspect the subsequent turn; never invent a setter, self-approve or bypass a rejection. Hold the rejected action and continue permitted work.
- Review: perform Ponytail before opening the PR. It does not replace the unchanged subsequent Claude API review. A protected self-skip is a gap; require authentic complete current-head/base/layer coverage and exact candidate CI. Revalidate changed inputs without altering Claude settings or launching unauthorized paid retries.
- Merge: hold additional publication until supported native stacking is verified. Semantic independence does not remove this project constraint. Merge serially, pin expected head, protect target ref/tip and revalidate movement. Preserve successor branches, sync clean main and restack/revalidate before the next merge.
- Closeout: automatically close the task worktree and archive the originating chat without routine approval or backup packages. Read back both separately; uncertainty retains the slot. Preserve only genuinely needed unpublished material through targeted handover/push. Never dispose of canonical, foreign, nested or active worktrees; report a concrete closeout hold instead.
- Controls: preserve download confirmation, quarantine and complete isolated scan requirements. Full access adds no authority. A new full pause freezes intake, implementation, new tests, pushes, PR creation, merges and closeout, including admitted work; relay its original evidence to both assigned workers and through the owning worker to the subagent. Collect local checkpoints and distinguish delivery, acknowledgment and in-flight actions; report the outstanding reply instead of claiming all work paused. A quota reset does not resume it; explicit owner resume requires live worker/operation/repository reconciliation. While running, prioritize evidenced security, open PRs, then eligible gate/task priority. Do not dispatch future-gate work or invoke advisory scans from priority alone. Apply newest owner quota/deadline rules, not superseded historical values.
