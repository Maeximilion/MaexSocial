# MaexSocial coordinator

A replacement coordinator starts here. [Current handover](CURRENT.md) is the dated queue and next action. This page is the standing operating agreement. The [coordination skill](../../.agents/skills/coordinate-project-chats/SKILL.md) describes desktop tools and merge checks. [Project status](../../docs/01_STATUS.md), [work packages](../../docs/07_WORKPACKAGES.md), GitHub issues and PRs remain authoritative for product decisions, dependencies and live checks.

## Own the record

Only the acting coordinator maintains this directory. A work chat sends its checkpoint directly to the authorized coordinator. It continues to own its issue, PR and [task handover](../../docs/handovers/README.md). Record the outcome here, link evidence and name the next owner. Keep raw messages, desktop IDs, credentials, personal data and machine-specific paths out of this public repository. Match chats locally by project, issue, PR and title. If two chats match, verify ownership before assigning either.

## Run the queue

- Keep this chat on coordination. Start with an existing issue or create one for distinct new work before dispatch. Assign each new issue or PR to a fresh named work chat. A completed chat may finish its own handover or archival checks. An unrelated follow-up belongs in a new chat. Name it `Issue #N · PR #M · Topic` when a PR exists. Count every unarchived work chat on the project roster toward a hard maximum of five, including idle, blocked and completed chats. Exclude the coordinator and review-only subagents. If the roster exceeds five, stop intake and retire completed chats first.
- Before starting a large issue or gate, drain to at most three unarchived work chats **including** the new one; use two when appropriate. List every smaller in-flight delivery, including chats still preparing their first PR. Hold the large PR until each predecessor has merged or the owner explicitly disposes of a blocked predecessor. Respect outstanding owner gates. Use dependency and priority order, then lower PR number for ties. For a stack merge the parent first, recheck the child, then merge one eligible PR at a time.
- MaexSocial uses Codex as primary implementer. Use Superpowers for orchestration and substantial plans. Choose the model and reasoning effort for the job and preserve model-routing pauses. Use Standard speed in the coordinator and new work chats. Enable Fast only when the owner explicitly requests it for that scope. Require verified GPT-6 Astra high for code review. During the owner's Claude pause, use the authorized `@codex review` fallback and verify a bot verdict on the candidate; the [skill](../../.agents/skills/coordinate-project-chats/SKILL.md) specifies merge gates. Other repositories keep their own primary programmer.
- At delivery verify the merge or other agreed completion, outstanding work, who owns it, evidence, and recovery of local changes. Record these before archiving. Desktop archival can remove attached worktrees. Before archiving, inspect tracked, untracked and ignored files and any nested worktrees. Preserve needed local-only material outside every affected checkout and verify recovery. If that cannot be established, hold archival. Read back the exact chat in the archive and verify its saved contents and worktree state before admitting a replacement. For a PR slot, both the merge and the verified archive must have happened. Close and archive completed work without a PR as such. It supplies no evidence of a PR merge. Reserve capacity before dispatch so concurrent completions cannot create a sixth chat. Closing a PR and merging it are different outcomes.
- A standalone owner `pause`, or an explicit deadline when reached, stops intake and merges. Relay to the connected work chats and their subagents. Track delivery, acknowledgement, unsaved changes and in-flight operations separately. Keep unfinished chats recoverable. Only a standalone owner `w` or `weiter` resumes a paused scope after live reconciliation. A dashboard refresh or a compacted context cannot resume it.

## Checkpoint and recover

1. Request a short report from each affected chat before foreseeable compaction, handoff, archive or shutdown. Use the same format at milestones: issue and PR, branch and full SHA, dirty or pushed state, checks/reviews actually seen, in-flight actions or subagents, blocker and one next action. A worker sends this to the coordinator rather than editing this directory.
2. Refresh [CURRENT.md](CURRENT.md) at a significant change, before deliberate compaction, and after pause acknowledgements. Record decisions, lane ownership, merge order, pending replies and the last owner control. Use a UTC timestamp and local timezone for deadlines. While running, commit and push the record from a separate worktree and verify the remote head. During a pause, save the latest checkpoint locally in that coordinator worktree and record its exact revision and any unpublished changes. Queue publication until owner resume. Git history preserves earlier checkpoints.
3. Compact at a stable boundary such as a completed merge batch or a settled pause, if the current interface offers the operation. Automatic compaction can occur before a report. Checkpoint during work so recovery does not depend on predicting it.
4. On entry, after compaction, or when replacing the coordinator, fetch the remote. Read this page, the latest published CURRENT.md (including any open coordinator-record PR newer than main) and the preserved local coordinator worktree. Use git worktree list and compare local status, commits and CURRENT.md to the remote. A newer local pause or unfinished handover takes precedence over an older published snapshot. Verify the expected branch and revision; do not pull into a dirty checkout. Reconcile the roster, open PRs, their true merge state, review coverage, gate decisions and in-flight processes. Recover missing reports from the authorized chats or their task handovers. Mark uncertainty as pending. Follow the newest verified owner control before taking action.
5. Keep the requested dashboard in the coordinator chat on an approximately ten-minute cadence, showing the repository-wide open PR count separately from the original delivered queue. During pause it reports status only.
